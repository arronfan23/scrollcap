# ScrollCap 界面与交互设计

### 查询与取舍

1. `desktop screenshot utility minimal --design-system`：返回了网页 Hero 布局，判定不符合桌面工具。
2. 按技能约定仅重试一次 `native desktop productivity utility --design-system`：返回 Flat Design、蓝绿色、低动效及清晰层级，风格部分适用；仍包含网页营销模块，明确弃用这些模块。
3. `keyboard focus modal --domain ux`：用于可见键盘焦点和弹窗内操作顺序。
4. `macOS accessibility layout --stack swiftui`：用于原生语义控件、可访问标签、尊重系统设置。

设计系统搜索结果是建议，不直接生成最终布局。网页的 Hero、Features、CTA、Google Fonts、手机断点并不适合本产品，均未采用。最终使用 AppKit 窗口、系统中文字体、SwiftUI 原生 Button/Picker/Menu/Stepper/TextField。

## 当前问题与设计回应

| 问题 | 用户后果 | 本次回应 |
| --- | --- | --- |
| 设置、权限、介绍、技术文案同等突出 | 用户难以判断先做什么 | 300 pt 设置栏配主预览区，开始动作固定在设置栏底部 |
| 未满足权限时易被当作点击无响应 | 反复点击开始、反复开权限 | 开始前显示权限行；保留明确系统权限警告；提供重新检查入口 |
| 自动和手动滚动规则混在长文案中 | 速度、方向、结束时机不清楚 | 模式与方向分组，分别给一句操作标准；高级项折叠 |
| 等待、录制、处理、空白共用同一视觉 | 不清楚当前进度 | 准备、采集、处理、结果分别呈现，等待显示进度反馈 |
| 标记固定区域时不知道哪段会拼接 | 标题、输入框被重复或正文被截掉 | 全图/有固定部分的两种布局，图内标注固定顶部、滚动正文、固定底部 |

## 视觉系统

- **结构**：紧凑品牌顶栏，左侧采集设置，右侧预览工作台，底部轻量 GitHub 支持行。没有侧边导航、营销卡片或独立首页。
- **窗口**：默认 1040 × 780，最小 900 × 750。设置区域可滚动，开始/结束动作固定；预览区吸收剩余空间。
- **色彩**：主按钮深蓝绿 RGB(0.025, 0.43, 0.46)，文字/图标强调色根据系统明暗切换；背景、正文、边框使用 macOS 语义颜色。
- **对比度**：主按钮深蓝绿与白色约 6.03:1。系统颜色最终仍需以明暗模式实际截图检查，不能仅凭静态色值推断所有组合。
- **排版**：中文系统字体；标题约 19–20 pt，分区使用 title3/callout，说明使用 caption。长说明允许换行，不截断主要操作。
- **间距**：主要内边距 24 pt，组间 24 pt，组内 8–12 pt；减少同一层级的装饰色和嵌套容器。
- **图标**：系统 SF Symbols；GitHub 使用现有官方 Octicons SVG，不使用箭头替代品牌。
- **动效**：不增加循环装饰动画、视差或大幅转场；等待使用系统 ProgressView，交互保留原生反馈。

## 交互流程

### 新建采集

1. 选择手动或自动、向下或向上。向上时说明从当前对话底部采集历史记录。
2. 查看权限。手动仅显示录屏；自动额外显示辅助功能。未开启显示「开启」和「重新检查权限」，开始失败仍显示原生警告。
3. 点击「框选窗口并开始」，检查时立即进入准备状态；沿用系统框选功能。
4. 标记正文：选择「有固定标题栏 / 输入框」或「整个区域都滚动」。切换整体滚动会同时设置两条边界为全图；手动拖动或输入边界后，布局状态由真实边界派生，避免控件与图像不一致。
5. 确认后开始采集，固定部分可选择保留一次或不截入。

### 标记边界

- 两条深蓝绿色线代表正文上下边界；固定顶部/底部加遮罩及文字标签。
- 鼠标在边界附近显示上下拖动光标，手柄尺寸增大。
- 点击某条边界后，上下键每次移动 1 个原图像素，Shift 每次 10 像素。
- 数值输入和 Stepper 可直接调整顶部/底部固定像素。
- 正文通常至少 140 px；小于 140 px 的图片只能保留到原图高度，小于 200 px 时默认全图，避免不可完成状态。
- Return 确认，Escape 取消。

### 采集中

- 延续非激活悬浮窗，避免点击工具导致目标应用失焦。
- 清晰显示模式、秒数、当前采集状态以及「结束并生成」。自动模式提醒保持目标窗口在前台，移开鼠标可以停止。
- 不鼓励切换应用查看工作台。主窗口中若进入采集态，同样提供结束动作，避免只有开始按钮被禁用。
- 自动滚动仍使用原有保护与结束条件，本次不修改算法或速度。

### 处理中

- 独立的生成状态、进度条、百分比和取消处理入口。
- 当前状态文字保留在画布下方。新结果未生成前不显示旧图裁剪控件，避免把旧图误认为新结果。

### 结果、裁剪与导出

- 标准结果显示尺寸、缩放选择、完成/调整裁剪、裁剪选项。
- 拖动四边或四角；「全图」用于一次看到上下边界。
- 「裁剪选项 → 精确调整四边…」提供上下左右裁去像素的即时输入与步进，作为拖动替代。
- 数值限制在图片范围内，至少保留 1 px；调用现有 `updateCrop`，不改变裁剪算法。
- PNG 保存、复制始终使用当前选区；「恢复原图」可逆。数值裁剪窗口的「取消」会恢复打开时的选区，Escape 同样取消，Return 完成。
- 不完整结果单独警告，并建议保留原视频；自动修正信息与警告分开显示。
- 开始下一次前提醒保存当前长图，避免用户误解结果持久化。

## 验证与交付标准

实际 GUI 验证由主任务在独立预览包中完成，避免重新签名、退出或覆盖用户正在使用的正式应用，避免破坏当前 macOS 授权和未保存结果。

需要覆盖：

- [ ] 默认 1040 × 780 与最小 900 × 750，开始/结束、裁剪与保存可见。
- [ ] 明亮与深色外观，主要正文和边界均可辨认。
- [ ] 手动/自动切换及向上/向下说明同步。
- [ ] 空白、准备、采集、处理、完整结果、部分结果、权限不足。
- [ ] 固定区域/全图切换、拖动、数值输入及最小正文约束。
- [ ] 四边拖动与精确数值裁剪，完成后保存和复制为裁剪结果。
- [ ] Tab 导航和焦点、Return / Escape、原生菜单动作。
- [ ] GitHub 官方图标保留，忙碌状态下支持链接不可用。
- [ ] 核心回归检查不因纯 UI 修改产生失败。

以上为覆盖目标，完整的实际通过项及验证边界见 [界面验证记录](UI_DESIGN_VALIDATION.md)。

## 体验独立设计预览

```sh
./scripts/build-design-preview.sh
```

输出为 `work/ui-design/ScrollCap Design.app`，身份独立于正式应用。打开后用「界面预览」菜单切换准备、处理、裁剪、部分结果、权限和明暗模式。点击开始可体验合成聊天素材的标记、演示采集、处理和保存流程。

预览包使用合成内容和演示权限，不读取真实屏幕，不发送系统滚轮，也不替换已安装的 ScrollCap。它用于评审界面和交互；真实截图仍使用正式应用。普通构建不包含 `DESIGN_PREVIEW` 编译分支。
